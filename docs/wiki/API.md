# API

The Quarkus API (`apps/api`) serves JSON under `/api`. Its OpenAPI schema is produced by the
build into [`openapi/`](https://github.com/zelytra/Librarius/tree/main/openapi) and the web
client is **generated** from it (orval, `apps/web/src/api/generated/` — never edited by hand).

## Rules every resource follows

- **Authenticated**: every resource is `@Authenticated` with a Keycloak bearer token.
- **Scoped to the caller**: an entity is read through the caller's id (`CurrentUser.id()`),
  never by its id alone. Another user's item answers 404, not 403.
- **Errors** are JSON `{ "message": "…" }` in French when meant for the reader (an import
  failure, an invalid ISBN), a bare status otherwise.
- **Changing a resource or a DTO** means regenerating the client in the same change:
  `cd apps/api && ./mvnw -B package -DskipTests && cd ../web && pnpm gen:api` (with
  `quarkus:dev` stopped). CI fails a pull request whose schema and client disagree.

## Endpoints

| Area | Endpoints | Notes |
|---|---|---|
| Library | `GET/POST /api/library`, `POST /api/library/bulk`, `GET/DELETE /api/library/{id}`, `PUT …/progress`, `…/rank`, `…/review`, `…/edition` (PUT a stored edition, POST a new one under the same work), `…/ownership`, `…/price`, `…/pages`, `…/format`, `…/language` (#566: the ISO 639 code the copy was read in, null clears it), `…/kind` | Two status families (#411): `status` is the reading status (`TO_READ` — formerly `OWNED`, still accepted —, `READING`, `READ`, `ABANDONED`), `ownership` whether the reader has the book (`OWNED`, `BORROWED`, `EBOOK`, `AUDIOBOOK` — #455 —, `WISHLIST`, `NOT_OWNED`); `WISHLIST` keeps a wish on the same edition in step. `book.pageCount` falls back on an estimate flagged `pageCountEstimated` (#414); `book.listPrice` is the publisher's price (#421). `…/review` takes `rating` (0.5 to 5 by half stars, #484), `review` and `shared` (private unless `true`). List is paged and filtered server-side (`kind`, `status`, `ownership`, `rank`, `minRating`, `q`, `standalone`, `format`, and `hideToRead` — #552: leaves out a to-read title unless another volume of its series has been read, which the library shelf sends on every shelf but the pile); sorts `recent` (default: latest of finished, started, added), `added`, `title`, `author`, `genre` (first normalised genre, unknown last), `rating`, and `manual` with `view=<id>` — the order the reader arranged one of their views in, the unplaced titles after (#451). `PUT …/kind` files the title under another kind for that reader only (#454): the copy moves to an edition of a work of that kind, keeping its ISBN, publisher, length and cover and everything the reader set. `POST …/bulk` applies several changes at once to up to 500 of the caller's titles (#457) and to every volume held of up to 200 `seriesIds` (#467): `status`, `ownership`, `format`, `kind` (#508, the same move as `…/kind`), `categoryId` or `clearCategory`, `rating` or `clearRating`, or `remove`; another reader's ids are skipped and `updated` counts the rest. A title added as `READ` is finished that day, one added as `READING` started that day. On `…/progress`, a move into `READING` starts today and a move into `READ` (or reaching 100 % while reading) finishes today — unless the request carries a date different from the stored one; resuming an `ABANDONED` title keeps its start |
| Wishlist | `GET/POST /api/wishlist`, `PUT/DELETE /api/wishlist/{id}`, `POST …/acquire` | acquiring moves a wish to the library (onto the existing title when the edition is already there); the budget counts the reader's estimate, else the market price |
| Series | `GET /api/series`, `GET /api/series/{id}`, `…/missing`, `…/follow`, `…/review`, `…/reviews`, `PUT …/rank` | `…/review` takes `shared` like a book review; `…/reviews` lists the shared ones the caller may see. The summary carries `authors` and `genre` (what the grouped library sorts a run on next to the one-shots), and carries owned/read counts, `lastActivity` and `rankCode` — the category most of the reader's volumes carry. `PUT …/rank` files every volume the reader holds under one category, or none (#451). The detail's grid runs to the series' `totalVolumes` and shows the catalog's cover for a volume the reader lacks (#602) |
| Works | `GET /api/works/{id}/editions`, `…/reviews`, `…/friends`, `…/external` | stored editions (empty and duplicate ones left out) plus the provider's, with their length, date and ISO language (Open Library's MARC codes converted), the reader's own first, then the French ones, then those with a cover (#480); reviews = readers' shared reviews the caller may see, with the average of their ratings; `friends` = the people the caller follows who read, own or wish for the title, through the visibility gate, with their status, ownership, category, and rating only when shared (#452); `external` = Open Library's readers (average, ratings, read, want to read — matched by work key or ISBN) and, for a manga, AniList's score (by id or exact title), credited and linked, cached 12 h in memory (#453); a stored edition without a release date takes the one of the provider's printing with the same ISBN (#568) |
| Authors | `GET /api/authors?q=`, `GET /api/authors/{id}`, `…/follow`, `…/external` | bibliography = the reader's titles plus the providers', asked in the reader's language (their profile locale, #601): the works printed in it first, then the others minus the translations filed as works of their own; `external` = the opening of the author's French Wikipedia article (CC BY-SA 4.0, credited), none for a disambiguation page (#453) |
| Catalog | `GET /api/catalog/search`, `GET /api/catalog/upcoming` | see [Catalog & book search](https://github.com/zelytra/Librarius/wiki/Catalog-and-Book-Search) |
| <a id="scan"></a>Scan | `GET /api/scan/{isbn}` | `match`: `ISBN`, `TITLE`, `SERIES_VOLUME` or `NONE`; `owned`, `wished`, `catalog` |
| Import | `POST /api/import/{booknode\|babelio\|mangacollec}` (by pseudo — Booknode only; Babelio and Mangacollec answer with the way to the collector), `POST /api/import/collected` (`source` `booknode`, `babelio` or `mangacollec`), `POST /api/import/csv`, `POST /api/import/json`, `GET /api/import/jobs/{id}` | asynchronous jobs, polled; see [Imports](https://github.com/zelytra/Librarius/wiki/Imports) |
| Export | `GET /api/export`, `GET /api/export/{jobId}` | JSON or CSV; large accounts in the background |
| Stats | `GET /api/stats`, `GET /api/stats/timeline`, `GET /api/stats/breakdown`, `GET /api/stats/value`, `GET /api/stats/readings?from=&to=` | timeline points carry `books`, `pages`, `byKind` and `pagesByKind`, plus `booksPerMonth`; pages count estimated lengths, `readWithPageCount` says how many read titles have a real one; `breakdown` covers every title read, dated or not; `value` is what the owned books and the wishlist are worth at the BnF publisher's price; `readings` lists the readings finished in a window (the current month by default) with their start, finish and `days`, both ends counted — the Stats calendar (#479) |
| Achievements | `GET /api/achievements`, `POST /api/achievements/seen` | server-authoritative (#287): evaluated on read, retroactive and silent the first time; `unseen` lists the unlocks to announce |
| Goals | `GET /api/goals`, `PUT/DELETE /api/goals/{year}?kind=` | one goal per year and kind (`BOOK` when `kind` is omitted), in books or pages; `GET /api/stats` returns `goals`, each with its `current` progress counted on that kind only |
| Categories | `GET/POST /api/categories`, `PUT/DELETE /api/categories/{id}` | Or, Argent, Bronze, Abandon are built in; a category of one's own carries the `color` (`#rrggbb`, 400 otherwise) picked on create and changed on `PUT` (#599) |
| Views | `GET/POST /api/views`, `PUT/DELETE /api/views/{id}`, `PUT /api/views/{id}/order` | the reader's saved library layouts (#451): `name`, `kind`, `shelf`, `sort` (`manual` included), `layout` (`grouped`/`flat`), `groupByCategory`, and `order` (`item:<id>` / `series:<id>` keys). 20 views at most (409 past it); an order key naming nothing of the reader's is dropped; another reader's view is 404 |
| Me | `GET/PATCH/DELETE /api/me` (`admin` says whether the caller holds the admin role, #488; `avatarVersion` is set while they have a picture; `country` (#573) is optional, an ISO 3166-1 alpha-2 code in either case, blank or absent clears it, 400 for a code naming no country), `PUT /api/me/terms` (#74: `{version}` records the acceptance of the terms in force at the server's time, 400 for any other version; `MeDto` carries `termsVersion`, `termsAcceptedAt` and `currentTermsVersion`), `PUT/DELETE /api/me/avatar` (#500: JPEG or PNG recognised by its magic bytes, 2 MB and 8000 px a side at most — 413 past either, 415 for anything else — cropped and re-encoded to a 256 px JPEG with no metadata), `DELETE /api/me/library`, `…/followers`, `…/following`, `…/blocked` | `DELETE /api/me` erases the account and its Keycloak login; `DELETE /api/me/library` empties the library (titles, readings, wishes, goals, own categories, followed series and authors, series reviews) and keeps the account, profile, social links and Home layout |
| Social | `GET /api/users?q=`, `GET /api/users/{id}/profile`, `GET /api/users/{id}/shelf?shelf=library\|toRead\|wishlist&page=&size=&q=` (#514: a page of a member's titles by title, behind the visibility gate — 404 out of reach, 400 another shelf; each title's `book` is a `MemberBookDto` with the catalog fields and `myItemId`, the caller's own copy of that work when they hold it, #513), `GET /api/users/{id}/avatar` (a member's picture for any signed-in member, `image/jpeg` with `nosniff` and `default-src 'none'`, 404 across a block or when none — the web app fetches it with the session, an `<img>` cannot carry the token), `PUT/DELETE /api/users/{id}/follow`, `PUT /api/users/{id}/follow/notify {notifyActivity}` (#516: whether following them notifies of their activity — on by default, 404 when not following; the profile carries `notifyActivity`, null unless the caller follows), `…/block`, `POST /api/reports` | a member's profile (#497): name, trusted badge, how the two accounts relate and the follow counts for anyone signed in; the reading side (`reading`: counts, pages read, read this year, top genres, current reads, latest finished, shared reviews — a rating only when shared) only through the visibility gate, `null` otherwise; 404 for an unknown id and across a block, either way. Members found by display name (two letters at least; the caller and blocked members left out), each with whether the caller follows them. Reports target `WORK`, `EDITION`, `SERIES`, or a shared review (`REVIEW`, `SERIES_REVIEW`, with the reasons `SPOILER`, `OFFENSIVE`, `SPAM`, `OTHER`) |
| Covers | `GET /api/covers/bnf/{ark}` | anonymous, resized and cached BnF cover thumbnail; see [Catalog & book search](https://github.com/zelytra/Librarius/wiki/Catalog-and-Book-Search) |
| Feedback | `POST /api/feedback`, `POST /api/feedback/errors` | a member's report from the bug button (#489): `kind` `BUG`, `IDEA` or `OTHER`, `message`, and the `page`, `appVersion`, `userAgent` and recent `logs` the app attaches unless unticked; `…/errors` is an error the web app did not expect (#490), one row per fingerprint (message + first stack line) counted each time — the app sends each error once per session, five at most. An unexpected server error (no other mapper took it) answers `{"message": "Erreur interne du serveur."}` with a 500 and is recorded the same way, with the endpoint and the stack trace; a `WebApplicationException` keeps its own answer and is not recorded |
| Feed | `GET /api/feed?page=&size=`, `PUT/DELETE /api/feed/{eventId}/reaction`, `POST /api/feed/{eventId}/comments`, `DELETE /api/feed/{eventId}/comments/{commentId}` | the social feed (#209, #210): what the caller (#511) and the members they follow **and may see** did — `FINISHED_READING`, `WISHLIST_ADDED`, `REVIEW_SHARED` — newest first, with `hasMore`; each item carries the book, the shared rating and review for a review event, the count per reaction, the caller's own (`myReaction`) and the flat comments (minus anyone a block stands between). One reaction per member (`LOVE`, `FUNNY`, `WOW`, `CLAP`, `SAD`; a new one replaces it); comments ≤2000 characters, deleted by their author only. Every write re-checks the visibility gate against the event's author: 404 once it is out of reach; a `FINISHED_READING` item carries `readingDays` (#569), how long the book was read — null without a start date |
| Notifications | `GET /api/notifications?page=&size=`, `GET /api/notifications/unread`, `POST /api/notifications/read`, `GET /api/feed/{eventId}` | the bell (#516, #211): newest first with `hasMore`, each `type` `ACTIVITY` (a followed member did something — only when `notify` is on for that follow and the visibility gate lets the caller see them), `REACTION` or `COMMENT` (on the caller's own event; comments can be switched off with `notifyComments` on `PATCH /api/me`), or `FOLLOW` (#544: the actor started following the caller — no event nor book; `followingActor` says whether the caller follows them back), with the actor, the event, its book (`MemberBookDto`), the comment or emote and `readAt`; never about oneself, nor across a block. `unread` → `{count}`; `read` marks everything read (204). `GET /api/feed/{eventId}` is one feed event, where a notification leads — 404 once out of reach |
| Admin | `GET /api/admin/feedback?page=&size=&status=`, `GET /api/admin/feedback/{id}`, `PUT /api/admin/feedback/{id}/status`, `GET /api/admin/users?page=&size=&q=`, `DELETE /api/admin/users/{id}`, `GET /api/admin/monitoring`, `GET /api/admin/countries` | realm role `admin` only (#488), 403 otherwise. `countries` (#573) = `[{country, members}]`, the largest first: a count per country from the country members gave in their profile, never who, and members who gave none are not counted. The members (#499): username, display name, email, creation date, picture, library size, last seen, `q` on the first three; deleting one runs the same erasure as `DELETE /api/me` — Keycloak first, then every row, 503 with nothing erased if Keycloak refuses, 400 on oneself, 404 unknown. the reports latest seen first with the reporter's name (null once their account is erased) and their triage `status` (#495: `NEW`, `SEEN`, `HANDLED`, `IRRELEVANT`; `status=` filters, 400 on another value), one in full with its logs — opening a `NEW` one marks it `SEEN`; `PUT …/status {status}` sets it (204, 400, 404); the monitoring = members active now (seen in the last 5 minutes), the last 30 days (members' reports, errors, active members), and whether the database and Keycloak answer (#491) |
| Agents | `GET /api/agent/feedback?page=&size=&status=`, `PUT /api/agent/feedback/{id}/status` | the reports for an agent or a script with no Keycloak session (#518): each report **in full** (message, logs or stack trace, page, version, user agent, reporter's name, occurrences, status), latest seen first, `status=` filtering as on the admin list; reading changes nothing, `PUT …/status {status}` triages (204, 400, 404). Every call sends the key in the `X-Api-Key` header — not `Authorization`, which is read as a Keycloak token — and gets 401 without it; with no key configured (`LIBRARIUS_AGENT_API_KEY`, see [Deployment](https://github.com/zelytra/Librarius/blob/main/docs/DEPLOYMENT.md#-cluster-secrets-manual-action-before-any-deployment)) the endpoint refuses everyone. Example: `curl -H "X-Api-Key: $KEY" "https://librarius.zelytra.fr/api/agent/feedback?status=NEW&size=100"` |
| Misc | `GET /api/genres`, `GET/PUT /api/dashboard/layout`, `GET /api/releases/upcoming` | |

## Who sees a shared review

A rating or review is private unless its author ticks "share". A shared one is listed by
`GET /api/works/{id}/reviews` and `GET /api/series/{id}/reviews` only to the readers
`VisibilityGate.canView` lets through: never anyone with a block in either direction between
them, otherwise everyone when the author's account is public, otherwise readers who follow
the author mutually. The average is computed over those visible ratings only, so it never
leaks a private one.

## Quotas

Per caller and per hour (#583): imports 10, exports 10, reports 20, error notices 120 —
past them the endpoint answers `429` with `Retry-After` and a `message`. Configured by
`librarius.quota.*.per-hour`; the catalog search keeps its own per-minute and per-day quota.
